# V0.1 后端学习笔记：最小 AI 客服请求链

## 本版完成了什么

V0.1 只完成一条最小客服问答链：接收一条消息，异步调用 OpenAI-compatible
Chat Model，返回助手文本和实际配置的模型名。

本版没有 LangGraph、工具调用、订单查询、数据库会话、SSE、RAG 或退款逻辑。
这些能力需要不同的状态和可靠性边界，提前加入会掩盖当前最重要的请求流。

```text
POST /v1/chat
  -> ChatRequest（Pydantic 校验）
  -> get_chat_service（FastAPI 依赖）
  -> ChatService.reply（业务用例）
  -> ChatModel（Protocol 边界）
  -> OpenAIChatAdapter（ChatOpenAI）
  -> OpenAI-compatible Responses API
```

返回方向相反：Adapter 返回文本，Service 生成 `ChatResult`，Route 再将它组装成
`ChatResponse`。每层只认识紧邻自己的协议。

## 推荐阅读顺序

1. `apps/agent-core/app/schemas/chat.py`
2. `apps/agent-core/app/services/chat.py`
3. `apps/agent-core/app/adapters/openai_chat.py`
4. `apps/agent-core/app/api/dependencies.py`
5. `apps/agent-core/app/api/routes/chat.py`
6. `apps/agent-core/app/api/exception_handlers.py`
7. `apps/agent-core/app/main.py`
8. 对照阅读 `apps/agent-core/tests/` 中同名测试

这个顺序从数据契约开始，逐步走到外部服务和应用组装，比从 `main.py` 同时追踪所有
导入更容易形成完整心智模型。

## 1. 类型标注不是运行时转换

```python
async def generate_reply(self, message: str) -> str: ...
```

`message: str` 和 `-> str` 类似 TypeScript 参数与返回值类型，主要服务于阅读、IDE 和
Mypy。Python 默认不会因为这个标注就在运行时拒绝整数，也不会自动把值转换成字符串。

`cast(ChatService | None, value)` 同样只帮助 Mypy，不会复制或转换对象。真正的运行时
输入校验由 Pydantic 完成。

## 2. Pydantic model 是运行时 DTO

`ChatRequest` 继承 `BaseModel`。`StringConstraints` 会在进入路由函数前执行：

- 去除首尾空白；
- 拒绝清理后的空字符串；
- 拒绝超过 2,000 个字符的消息。

这与 TypeScript `interface` 的关键差异是：`interface` 编译后不存在，不能验证外部
JSON；Pydantic model 会在运行时解析和校验。失败时 FastAPI 直接返回 `422`，路由和
Service 都不会执行。

`ErrorResponse` 使用固定字符串 `Literal` 约束错误码，使拼错的错误码在测试或类型检查
阶段更容易被发现。

## 3. FastAPI 依赖注入与 NestJS provider

`main.py` 在 lifespan 启动阶段创建一次 `ChatService`，放进当前 FastAPI 实例的
`app.state`。它的生命周期类似 NestJS 默认 singleton provider，但不是 Python 全局变量。

```python
service: Annotated[ChatService, Depends(get_chat_service)]
```

FastAPI 会在请求时调用 `get_chat_service()`，但该函数只取出应用中已有的实例。也就是：

- 依赖函数每个相关请求都会执行；
- ChatService 和 ChatOpenAI 客户端不会每个请求重新创建；
- 多个并发请求可以共享无请求级可变状态的 Service。

没有配置 Key 时，应用仍可启动和提供健康检查；只有聊天依赖会抛出
`ChatNotConfiguredError`。

## 4. Protocol 是最小接口边界

`ChatModel` 是一个 `Protocol`：任何对象只要提供相同签名的异步 `generate_reply()`，
就可以交给 `ChatService`。它类似 TypeScript 的结构类型接口，不要求显式继承。

本版使用 Protocol 有一个明确收益：生产环境注入 `OpenAIChatAdapter`，自动化测试注入
Fake Model。Service 不需要导入 LangChain，也不需要在测试中创建真实客户端。

除此之外没有继续增加 repository、manager 或 factory 层，因为 V0.1 尚没有对应复杂度。

## 5. async/await 表示等待时让出执行权

从 route、service 到 adapter 的调用链都是异步的：

```python
result = await service.reply(payload.message)
response = await self._client.ainvoke(messages)
```

等待网络响应期间，事件循环可以处理其他请求。`await` 不代表启动新服务或新线程，也不
代表函数已经结束；它会在被等待的操作完成后，从下一行继续执行。

应用 lifespan 中的 `yield` 覆盖整个服务运行期。服务退出后才进入 `finally` 并释放
SQLAlchemy engine，不是启动完成后立即释放。

## 6. 配置只在边界处读取

`Settings` 负责从环境变量加载配置，其他层接收已经解析好的值。Key 使用 `SecretStr`，
避免对象被打印时直接显示真实内容。

本版配置项：

```dotenv
OPENAI_API_KEY=
OPENAI_BASE_URL=
OPENAI_AGENT_MODEL=gpt-4.1-mini
OPENAI_REASONING_EFFORT=
OPENAI_USE_RESPONSES_API=true
OPENAI_REQUEST_TIMEOUT_SECONDS=30
```

仓库根 `.env` 适合前后端共享配置；`apps/agent-core/.env` 更适合后端专属覆盖。当前设置中
后者优先级更高。空的可选值会被 validator 统一转换为 `None`。

兼容服务只需要提供 `OPENAI_BASE_URL`、Key、模型及其支持的 reasoning effort。
`AI_PROVIDER_NAME` 没有进入配置，因为它不参与 ChatOpenAI 的请求路由。

## 7. 错误在 API 边界统一翻译

Adapter 将 SDK 异常转换为项目自己的异常；Service 不返回 HTTP 状态码；全局 handler
最后将领域异常映射为稳定的状态码和错误码。

```text
认证/权限失败 -> 503 / chat_authentication_failed
限流          -> 429 / chat_rate_limited
超时          -> 504 / chat_timeout
其他上游失败  -> 503 / chat_provider_unavailable
未配置        -> 503 / chat_not_configured
```

日志只记录异常类型和路由路径，不记录 Key、完整用户消息或 SDK 原始错误文本。返回给前端
的消息也不直接使用上游异常内容。

## 8. 测试替身与测试边界

- Schema 测试运行时校验和序列化。
- Service 测试注入 Fake Chat Model。
- Adapter 测试替换内部客户端，验证消息和 SDK 异常映射。
- Route 测试通过 FastAPI dependency override 注入 Mock ChatService。
- HTTPX ASGI Transport 在进程内请求应用，不监听本地端口。

因此自动化测试不需要 `OPENAI_API_KEY`，不会产生真实 API 费用。真实提供商请求只属于手动
smoke test，不能代替可重复的自动化测试。

## 可手动尝试的练习

1. 在 schema 测试中加入恰好 2,000 个字符和 2,001 个字符的边界案例，观察 Pydantic 结果。
2. 给 Fake Model 增加 10 毫秒异步等待，同时启动两个 `ChatService.reply()`，观察总耗时。
3. 临时将 route 测试中的 Fake Service 改为返回空文本，判断空文本应该在哪一层被拒绝。
4. 不配置 Key 启动应用，只访问 `/health/live` 和 `/v1/chat`，比较两个端点的职责边界。

前三个练习不需要真实 Key。第四个练习也不会调用 OpenAI；只有配置真实 Key 且提交有效
聊天请求时才会发生在线调用。
