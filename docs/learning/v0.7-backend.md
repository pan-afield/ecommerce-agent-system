# V0.7 后端学习记录

## 本轮完成

- `ingestion_tasks` 使用 `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED` 状态。
- 任务领取生成 `attempt_id`，完成和失败回写必须匹配当前执行凭证。
- 任务状态和 Outbox 事件在同一数据库事务中写入。
- Outbox 发布使用 `publish_attempt_id` 租约，避免两个发布者同时确认同一事件。
- 超时租约可以释放，发布入口会先回收再领取。
- Redis 客户端由应用 lifespan 创建和关闭；Redis 不可用时缓存读写和失效都会降级。
- RAG 缓存 key 包含查询、embedding 模型、向量维度和 `limit`。
- 知识库导入成功后才执行 RAG 缓存失效。

## 并发时间线

任务执行：请求 A 领取任务后暂停，请求 B 不能领取同一任务；如果 A 的租约过期，B 可以重新领取。A 之后携旧凭证回来时，状态更新条件不匹配，因此不能覆盖 B 的结果。

Outbox 发布：发布者 A 获得租约 A 后进程退出，回收后发布者 B 获得租约 B。A 的迟到确认会返回失败，不会把 B 的租约标记为已完成。

## Redis 边界

PostgreSQL 仍是任务、订单、退款、Checkpoint 和知识库的事实来源。Redis 只保存 RAG 查询结果；缓存未命中、连接失败或写入失败都不改变主流程结果。

当前缓存失效采用导入成功后的 `SCAN` 删除。一个正在执行的旧查询仍可能在失效之后写回旧结果，短时间内存在竞态；后续若需要严格避免，应引入知识库版本号并把版本纳入 key。
