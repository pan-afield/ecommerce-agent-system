# Ecommerce Agent System 开发与学习进度计划

> 更新日期：2026-08-10

## 1. 计划基准

本项目同时承担产品实现和 Python 学习两个目标，开发方式分为：

- 前端：由 Codex 对话直接实现，用户主要负责需求确认、视觉检查和前后端联调验收。
- 后端：采用教学模式。用户亲自编写生产业务代码，Codex 每次提供一个小步骤，并负责讲解、审查、自动化测试、Mock、验证和学习文档。
- 单次学习时间：固定按 3 小时统计和安排。
- 推荐频率：每周 6 次，保留一天用于休息、复盘或处理计划外问题。

由于后端采用教学模式，整体速度会比直接代写慢约 30%～50%，但这部分时间计入 Python、FastAPI、数据库和 Agent 工程的有效学习时间。

按当前已完成内容重新估算，整个项目预计还需要 **130～186 个有效小时**：

- 固定 3 小时/次：约 44～62 次学习班。
- 每周 6 次时，理论投入约为 18 小时；加入教学、复盘、返工和计划外问题缓冲后，正常目标仍为 10～14 周，安全目标为 16 周。
- 当前没有连续记录每次学习班的实际用时，因此剩余工时按各版本范围估算，不用未经记录的时间制造精确进度。

## 2. 当前状态

- `POST /v1/chat`、Pydantic 输入校验、ChatService、ChatModel Protocol 和 ChatOpenAI Adapter。
- OpenAI-compatible Base URL、模型、reasoning effort、Responses API 和请求超时配置。
- 稳定的聊天错误码、上游异常脱敏和不记录完整用户消息的日志边界。
- 可交互聊天工作台、Next.js `/api/chat` 代理、运行时响应校验、失败状态和重试交互。
- 后端学习文档 `docs/learning/v0.1-backend.md`。
- 后端 Pytest 最近验证为 **51 passed**；前端 Vitest 本次验证为 **21 passed**。
- 用户已在真实浏览器中完成前端、Next.js 代理、FastAPI 和实际 AI 服务的端到端验收。

当前 V0.1 完成度为 **100%**。工作区中仍有前端未提交文件，但这属于版本管理收尾，不影响功能验收结论。

V0.2 已开始规划：

- 已确定主题为 PostgreSQL 订单数据与 Python async 数据访问。

- 已确定 Repository、Service、API 的最小分层，以及 Decimal 金额、物流排序和 Fake Repository 测试范围。
- 已在 `AGENTS.md` 增加仅适用于后端的并发教学规则。

V0.2 尚未实现：

- 订单 Pydantic schema、SQLAlchemy 映射、AsyncSession、Repository、Service 和 API。
- 数据库集成测试及 `docs/learning/v0.2-backend.md`。

当前 V0.2 约完成 **5%**，处于架构确认和第一个 Python 学习步骤开始前。

按版本累计工作量权重折算，当前整个项目约完成 **6%～7%**：V0.1 对应的首个 6% 已全部完成，V0.2 只完成了其规划部分；后续 Agent、退款、RAG 和可靠性版本仍占主要工作量。

| 周期 | 目标 | 阶段成果 |
|---|---|---|
| 当前 / 第 1 周 | 完成 V0.2 | 理解关系模型、异步数据库访问和订单归属校验 |

## 5. 单次学习班安排

### 3 小时固定学习班

| 环节 | 时间 | 内容 |
|---|---:|---|
| 回顾 | 15 分钟 | 确认当前状态和本次验收目标 |
| 概念 | 35 分钟 | 讲解请求链、Python 概念和设计原因 |
| 编码 | 90 分钟 | 用户完成后端业务代码 |
| 验证 | 30 分钟 | 自动化测试、类型检查和调试 |
| 复盘 | 10 分钟 | 总结知识点并更新学习文档 |

前端任务可以在后端学习过程中异步推进，但每个版本仍应预留约 15%～20% 的时间用于接口契约确认、页面检查和联调验收。

## 6. 版本完成度计算

每个版本按以下权重统计：

| 项目 | 权重 | 完成标准 |
|---|---:|---|
| 后端知识点理解 | 10% | 能描述主要请求链和关键设计原因 |
| 后端业务代码 | 35% | 用户完成本版本生产业务代码 |
| 自动化测试与错误处理 | 20% | 正常、错误和关键边界测试通过 |
| 前端实现与联调 | 20% | 页面能够消费真实接口并正确展示状态 |
| 手动验收与学习复盘 | 15% | 完成验收场景和版本学习记录 |

只有五部分全部完成，版本才标记为 100%。不以“文件已经创建”或“接口可以返回一次结果”作为版本完成标准。

## 7. 每版验收清单

每个版本结束前必须满足：

- 本版约定的业务闭环可以演示。
- 自动化测试不调用真实付费 API。
- 相关测试、Lint 和变更范围类型检查通过。
- 前后端接口契约一致。
- 服务重启、失败路径或权限边界按本版风险完成验证。
- 学习文档记录本版 Python 和 AI 知识点。
- 明确记录未覆盖场景和下一版本边界。

## 8. 计划更新规则

- 每完成一个版本，更新当前状态、实际工时和偏差原因。
- 如果实际工时超出上限 30%，先判断是学习深挖、需求扩张还是技术阻塞，不直接压缩测试时间。
- 新功能只能进入当前版本明确范围或后续版本待办，不应临时插入正在学习的后端步骤。
- 前端提前完成不会自动提高版本完成度，必须等待后端、测试、联调和复盘共同完成。
- 时间不足时优先保证当前版本闭环，企业级增强留到 V0.7，不跨版本提前铺设。
